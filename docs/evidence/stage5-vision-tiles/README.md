## 2. Mechanism Findings: Token Scaling, Tile Edges, and Diagnostics

1. **Image-token scaling and resolution ceiling:** `deepseek-flash` (`detail: original`) scales image tokens with pixel dimensions up to an internal ceiling already reached at `2400×1080` (`1,980` prompt tokens): upscaling 2× to `4800×2160` in **Diag (a)** yields the exact same `1,980` prompt tokens (`0` extra image tokens) and the same spliced `"Unités inactives etzen"` error as `#82` Run 2. Cropping down to `1440×648` (`36%` area) drops `prompt_tokens` by `432` to `1,548` per tile (`~55%` of full-image tokens, or only `~1.5×` tokens per pixel area / `~1.2×` linear sharpness).
2. **Breakdown of tile failure modes on the probe:**
   - **Screenshots becoming `not_checked` due to a tile:** **`0`** (all 4 tiles returned `readability = "readable"` and valid schema v2 JSON).
   - **False findings caused by tile edges:** **`7` FPs** (`6` sub-word hallucinations + `1` whole-word fragment), all emitted by `bottom-right` `(960, 432, 2400, 1080)` where its left border at $x = 960$ slices through seven German gameplay option labels ($x \in [572, 1686]$): `"gehen der Einheiten"`, `"ch Entfernung durchgehen"`, `"lick bewegen"`, `"ngen Klick bewegen"`, `"h Menge sortieren"`, `"für 'Nächste Runde'"`, and `"es Benachrichtigungsverlaufs"`.
   - **Duplicates surviving the `(text, full_region)` merge & grid-line shift note:** **`0` surviving duplicates** on the probe screenshot. Note on region mapping: mapping a tile's local 3×3 cell by its centre can shift a text near a full-screen 3×3 grid boundary by one cell (e.g., `"Unités inactives"` at $x \in [644, 1044], y \in [249, 292]$ was reported in local `center` of `top-left`, whose centre $(720, 324)$ maps to full-screen `top-left`, matching the label's `top-left` region whereas `#82` full-image runs reported `center`).
3. **Why `overflow` (`"Hilfe"`) was missed (Diag b):** `bottom-left` `(0, 432, 1440, 1080)` missed `"Hilfe"` (`0` findings). When **Diag (b)** isolated the `?` button in a native `600×300` crop `(0, 780, 600, 1080)` (`1,172` prompt tokens), the model read `"Hilfe"` clearly (`confidence: 0.9`) but classified it as **`wrong_language`** instead of **`overflow`** (a D-026 type-free detection TP, `0/1` exact class). Thus, the `0/6` `overflow` recall in `#82` is a visual-reasoning limitation on button-bounds overflow rather than unreadable small text, and removing surrounding German UI context in tight crops causes German words to be misclassified as `wrong_language`.

## 3. Conclusion

**Negative result:** `2×2` tiling is **not adopted** for `deepseek-flash` (the full image stays the only mode; no decision entry added to `docs/decisions.md`). Tiling increases cost and latency by `~4×`, gains only `~1.2×` linear token resolution per tile, does not recover `overflow`, and degrades precision from `1.000` to `0.111` on the probe screen due to `truncated_text` false positives along tile seams. The probe and diagnostics ran with a `--tiles 2x2` option of `l10n-eval` that was not merged (D-059); the code stays in the history of PR #83 (commit `0955b69`) for a later provider comparison.
